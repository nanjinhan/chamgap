4. 끝나지 않은 일은 "끝났다"고 말하지 않는다. 확인 못 한 것(실물 하드웨어 등)은 확인 못 했다고 말한다.

## 1. 목표 (사용자 말 기준)

> "아두이노 코드랑 이 웹앱이 잘 연결돼서, 진짜 센서값이 웹에 보이고, 웹에서 뭘 누르면 아두이노에서 실행되는 것"

- 구역 3개(Z1·Z2·Z3)의 ESP32가 센서값(온습도 A·B, 토양 A·B, 무게, 12V, 누수)을 보내고 웹앱이 실시간으로 보여 준다.
- 웹앱에서 급수(mL)·정지·보정 명령을 누르면 ESP32가 실행하고 결과가 웹에 돌아온다.
- **인터넷으로 어디서나** 접속한다. **Supabase 무료**를 쓴다 (사용자가 이전에 Supabase 무료로 아두이노 연결을 해 본 적이 있다).
- **로그인 없음** (팀이 하나만 쓰는 앱).

원래 목적(요구사항지시서 1.1): 값을 보여 주는 데서 끝나지 않고 "이 값을 믿어도 되는지, 아니면 무엇을 확인할지" 알려 주는 진단. → 새 구조에서 진단을 어디에 둘지는 **미정** (8장 질문 1).

| 항목 | 원래 지시서 v1.0 | 새 결정 |
|---|---|---|
| 연결 경로 | ESP32 ─USB 시리얼/로컬 MQTT─▶ 노트북 파이썬 서버 ─▶ 웹앱 | **ESP32 ─WiFi─▶ Supabase(무료) ◀─▶ 웹앱** |
| 웹앱 호스팅 | 노트북 서버가 띄움 (같은 WiFi에서만) | **Vercel(무료)** — 인터넷 어디서나 |
| 인터넷 공개·로그인 | 범위 밖 | 인터넷 공개 O, **로그인 없음** (주소는 팀 안에서만 공유) |
| 파이썬 브리지 서버 | 필수 (진단·안전 검사·저장 담당) | **필수 아님.** 진단 서버(P6, 선택)와 가짜 ESP32(P3)로 재사용 |
| 진단 | 필수 | **(가) 값 보기 + 명령을 먼저 끝까지** 만들고, (나) 진단은 P5 뒤에 할지 정한다 (사용자가 제안을 받아들임, 2026-10-23) |
| 웹 시험 모드 화면 | 있음 | **제외** (시험 스케치는 아두이노 IDE 시리얼 모니터로). v2.0에서 정함 — 사용자 확인 대기 |
| 명령 전달 | 서버 대기열 | ESP32가 Supabase Realtime으로 받고, 만든 지 10초 넘은 명령은 `expired` (안전) |
| 급수 전 안전 검사 (SAFE-03) | 서버가 검사 | **ESP32 펌웨어가 최종 검사** (15초 상한, 12V, 누수, 하루 한도, 유량 보정, 오래된 명령 무시) + 웹은 미리 안내만 |
| 저장 | 노트북 SQLite + JSONL | **Supabase Postgres** |

### 새 구조 그림
```
[ESP32 Z1~Z3] ──WiFi(HTTPS)──▶ [Supabase 무료: Postgres + Realtime]
   센서값·사건 올림                 readings / events / nodes / commands 표
   commands 표에서 명령 가져가 실행  ▲
                                   │ 실시간 구독 · 명령 넣기
                          [웹앱 (React, Vercel)]  ◀── 폰·노트북 어디서나
(선택) [파이썬 진단 서버, 노트북] ── Supabase 값을 읽어 진단을 diagnostics 표에 기록
```

### 3.3 펌웨어 `firmware/node/` — USB 시리얼 버전 (2026-10-23)
- 사용자가 지금 실제로 단 센서: **DHT11 1개(온습도 A 자리, SHT31 납땜 전 임시)**, **토양 2개**, **로드셀+HX711(DT26·SCK27)**. 사용자가 준 로드셀 시험 코드는 bogde HX711 라이브러리.
- `node.ino` + `config.h`(센서 켜고 끄기·핀). 규약은 지시서 4장 그대로, 시리얼 JSON + 명령(info·status·tare·cal·soilcal·flow·interval·id·reboot·pump·water·stop). 펌프 안전(15초·쿨다운·50/300mL·12V·누수·scale_dead) 포함. `flowcal`은 아직(P2).
- 규약 밖 추가: data `weight_raw`(보정 전 원시값), info `sensor_a`·`*_present`(미설치 센서 구분). 웹 홈이 "미설치"·"raw … · 보정 전"으로 보여 준다.
- 이 노트북 arduino-cli로 **컴파일 통과**. 같은 형식의 가짜 줄(socket://)로 서버·웹 표시 확인. **실물 보드 업로드는 아직** (사용자가 함). **DHT_PIN은 기본 4 — 사용자에게 실제 핀 확인 필요.**
- 서버: mock 모드 기록은 `data/mock/`·`logs/mock/`에 따로 저장하도록 바꿈 (실제 기록과 섞이지 않게).

### 3.5 Supabase `supabase/` — P1 완료 (2026-10-23)
- 조직 `chamgap`(Free), 지역 **도쿄**(ap-northeast-1, 서울에 장애가 있어 도쿄로 잡힘 — 그대로 쓰기로 함). **Project URL: `https://luikttaomstcdvbdcmhk.supabase.co`**. 공개 키(`sb_publishable_…`)는 `web/.env.local`·`firmware/node/secrets.h`에 있다 (둘 다 git 제외. 공개 값이라 Vercel 환경변수에도 이것을 넣는다)
- `schema.sql`을 SQL Editor에서 실행 성공 ("Run and enable RLS" 선택 → `private.secrets`에도 RLS 켜짐, 동작에 문제 없음). 첫 실행은 `commands` CHECK의 정규식을 `||`로 이어 붙여 `~`와 우선순위가 섞여 실패 → 한 문자열로 고침
- `device_key`·`diag_key`는 **사용자 메모장에만** 있다 (채팅·GitHub 금지). device_key → ESP32 `secrets.h`, diag_key → 진단 서버(선택). DB 비밀번호·secret(service_role) 키는 받지 않는다 — 웹·ESP32 어디에도 필요 없다
- 권한 확인 **`node supabase/check.mjs`** (`web/.env.local`의 공개 키 사용) — 2026-10-23 **23개 모두 통과**: 읽기 O(표 6개·`latest_readings`·`history()`) / `private.secrets` 안 보임(404) / 기기 키 없는 readings·nodes·events(evt)·diagnostics 쓰기 거부(401, 42501) / `pump 1000`·`help`·`water 10; reboot` 거부(400, 23514) / `water 10` 허용 / 속인 status·created_at은 트리거가 덮어씀 / 기기 키 없이 명령 상태 변경·삭제는 0줄(RLS) / 10초 넘은 명령 `expired`(pg_cron 매분, 이번엔 15초 만에). 실행할 때마다 node `TEST` 명령 1줄이 남는다 (7일 뒤 자동 삭제)
- 확인된 것: 새 공개 키(`sb_`로 시작)는 **`apikey` 헤더 하나로** 동작한다 (`Authorization: Bearer`에는 넣지 않는다 — JWT가 아님). P2 펌웨어·P3 가짜 ESP32도 같게
- **아직 확인 못 한 것**: 기기 키(`x-device-key`)로 쓰기가 실제로 되는지 (P2/P3에서), Realtime 구독 (P4에서)

## 5. 제안 설계 (P1·P2에서 확정)

### 5.1 Supabase 표
| 표 | 쓰는 쪽 → 읽는 쪽 | 내용 |
|---|---|---|
| `readings` | ESP32 → 웹 | 주기 측정값 한 줄 = 한 행. 열은 지시서 4.2 `data` 키 그대로 (`node, seq, temp_a, rh_a, temp_b, rh_b, soil_a_mv, soil_a, soil_b_mv, soil_b, hx_ok, weight_g, weight_sd, v12, leak, pump, rssi`) + `created_at`(서버 시각) + `raw jsonb` |
| `events` | ESP32 → 웹 | `boot`, `pump_on`, `pump_off`, `refused`, `info` 등 (`node, kind, payload jsonb, created_at`) |
| `nodes` | ESP32 → 웹 | 구역별 마지막 상태·보정값(`info` 내용), `last_seen`. ESP32가 upsert |
| `commands` | 웹 → ESP32 → 웹 | `id, node, cmd('water 10' 같은 지시서 4.3 명령 문자열), status(pending→sent→done/failed/expired), result jsonb(ack), created_at, done_at` |
| `diagnostics` | 진단 서버 → 웹 | (P6 선택) 지시서 6.2 형식 |

### 5.2 명령 흐름과 안전
1. 웹이 `commands`에 `pending`으로 넣는다 (허용 명령만: water, stop, tare, cal, soilcal, flow, interval, info, status, reboot, flowcal — DB CHECK 제약으로 막는다).
2. ESP32가 1~2초마다 자기 구역의 `pending`을 가져가 `sent`로 바꾸고 실행, ack를 `result`에 넣고 `done`/`failed`.
3. **만든 지 10초가 넘은 명령은 실행하지 않고 `expired`** (ESP32가 꺼져 있다 켜졌을 때 오래된 급수 명령이 실행되는 사고 방지).
4. ESP32 안전(최종 판단, SYS-02 유지): 부팅 시 펌프 OFF, 1회 최대 15초 후 스스로 끔, 12V 없음·누수면 거부·즉시 끔, 끈 뒤 3초 쉬기, **하루 300mL 한도와 유량 보정 확인도 ESP32가** (하루는 NTP 시각 기준).
5. `stop`은 다른 명령보다 먼저 처리.
6. 로그인이 없으므로 anon key로 누구나 `commands`에 넣을 수 있다. 쓰기 권한은 RLS로 최소화하고, ESP32가 쓰는 표(readings 등)는 **기기 비밀값 헤더**(예: `x-device-key`)를 RLS 조건으로 확인하는 방식을 검토한다.

### 5.3 무료 등급에서 주의할 것 (P1에서 최신 정책 확인)
- 5초 × 3구역 ≈ 하루 5만 행 → 무료 DB 용량(약 500MB)을 몇 주 만에 채울 수 있다 → **보관 기간(예: 14일) 자동 삭제** 또는 주기 늘리기.
- 무료 프로젝트는 오래 쓰지 않으면 일시정지될 수 있다 (정책 확인 필요).
- ESP32 HTTPS: 처음에는 `WiFiClientSecure::setInsecure()`로 단순하게, 이후 루트 인증서 고정 검토.

### 5.4 하드웨어 (지시서 1.3 그대로 가정 — 8장 질문 3으로 확인)
SHT31 A 0x44 / B 0x45 (SDA21·SCL22), SEN0193 A GPIO32 / B GPIO33, HX711 DT26·SCK27, 펌프 DFR0457 GPIO25(+10kΩ 풀다운), 12V 감지 GPIO34(47k/10k), 누수 GPIO35(선택). 보정값은 NVS 이름공간 `chamgap`.

## 6. 지금 상태에서 실행하는 법 (Windows)

```bat
:: 서버 (mock: 가짜 ESP32 3대)
cd server
.venv\Scripts\activate
python -m chamgap --mode mock --mock-speed 5      :: http://localhost:8000/docs

:: 웹 (다른 터미널)
cd web
npm run dev                                        :: http://localhost:5173  (데모: /dev/fx)

:: 확인
cd server && pytest && ruff check .
cd web && npm run lint && npx tsc -b && npm run build
```
- 서버 가상환경이 없으면 `server\run_server.bat`이 만들어 준다. 웹은 `npm install` 필요.
- 개발 환경: Python 3.12, Node 24, npm 11, Windows 11. 브라우저 화면 확인은 playwright-core + 설치된 Chrome(`C:/Program Files/Google/Chrome/Application/chrome.exe`)으로 스크린샷을 찍어 했다 (도구는 프로젝트에 넣지 않음).

## 7. 지킬 관례

- **웹**: TS strict, `any` 금지. `src/components/react-bits/`·`src/components/ui/` 원본은 고치지 않고 `src/components/fx/` 래퍼를 쓴다 (꼭 고치면 `// MODIFIED:` 주석). 모든 래퍼는 움직임 줄이기 지원. 상태는 색+글자+아이콘(UI-05). **모두 정지 버튼은 모든 화면에 항상, 확인 창 없이. 급수는 1초 길게 누르기로만.** 진단 문구를 웹에서 지어내지 않는다 (진단 서버가 주는 것만 표시).
- **서버**: ruff 기본 규칙, pytest, 시간은 `Clock` 주입(테스트에서 건너뛰기).
- **펌웨어**: 비밀값(WiFi 비밀번호, Supabase 키, 기기 비밀값)은 `secrets.h`에만, 저장소에는 `secrets.example.h`만. 시리얼(115200, 한 줄 JSON) 출력은 계속 유지해 USB로도 볼 수 있게.
- **웹 환경변수**: `web/.env.local` (git 제외), Vercel에는 프로젝트 설정의 Environment Variables로.
- 단계가 끝나면 이 문서 3장·4장을 갱신한다.

## 8. 사용자에게 확인할 것 (열린 질문)

1. ~~진단 기능~~ → 정함: (가)를 먼저 끝까지, (나) 진단 서버는 P5 뒤에 할지 정한다.
2. **Supabase 프로젝트**: 사용자가 만들고 Project URL과 anon key를 알려 준다 (P1에서 안내).
3. **실제 하드웨어 구성**이 5.4와 같은지, 구역이 정말 3개인지, 누수 센서·12V 감지를 쓰는지 (지시서 11장 미정 사항).
4. **WiFi**: ESP32는 2.4GHz만 된다. 현장 WiFi 이름·비밀번호는 사용자가 `secrets.h`에 직접 넣는다.
5. 사용자가 **예전에 Supabase로 만든 아두이노 코드**가 있으면 참고용으로 받는다 (없어도 진행 가능).
6. 지시서 v2.0에서 웹 시험 모드는 **제외**로 정했다 — 사용자가 다르게 원하면 되돌린다.
7. 지시서 v2.0에서 새로 정한 값들이 괜찮은지: 명령 만료 10초, 데이터 보관 14일, 측정 주기 5초(한도에 가까우면 10초), 하루 300mL·1회 50mL.
