## 0. 가장 중요한 작업 규칙 (사용자 요청)

1. **한 번에 한 단계만** 만든다. 끝나면 ① 무엇을 만들었는지 ② 어떻게 확인했는지 ③ 사용자가 직접 확인하는 방법을 짧게 소개하고 **멈춘다.** 사용자가 "다음/진행"이라고 해야 다음 단계로 간다.
   - 이전 세션에서 확인 없이 여러 단계를 이어서 만들어 사용자가 불만을 표시했다. 절대 반복하지 않는다.
2. 사용자는 **아두이노(ESP32) 코드까지 전부 AI가 만들어 주기**를 원한다. 사용자가 직접 코딩하지 않는다고 가정하고, 사용자가 해야 하는 일(Supabase 가입, 키 복사, 보드에 올리기)은 클릭 단위로 안내한다.
3. 모든 사용자용 문구는 한국어, 코드·변수 이름은 영어.
4. 끝나지 않은 일은 "끝났다"고 말하지 않는다. 확인 못 한 것(실물 하드웨어 등)은 확인 못 했다고 말한다.
5. 이 문서를 단계가 끝날 때마다 갱신한다 (특히 "3. 지금까지 한 것"과 "4. 앞으로 할 일"의 체크).

## 1. 목표 (사용자 말 기준)

> "아두이노 코드랑 이 웹앱이 잘 연결돼서, 진짜 센서값이 웹에 보이고, 웹에서 뭘 누르면 아두이노에서 실행되는 것"

- 구역 3개(Z1·Z2·Z3)의 ESP32가 센서값(온습도 A·B, 토양 A·B, 무게, 12V, 누수)을 보내고 웹앱이 실시간으로 보여 준다.
- 웹앱에서 급수(mL)·정지·보정 명령을 누르면 ESP32가 실행하고 결과가 웹에 돌아온다.
- **인터넷으로 어디서나** 접속한다. **Supabase 무료**를 쓴다 (사용자가 이전에 Supabase 무료로 아두이노 연결을 해 본 적이 있다).
- **로그인 없음** (팀이 하나만 쓰는 앱).

원래 목적(요구사항지시서 1.1): 값을 보여 주는 데서 끝나지 않고 "이 값을 믿어도 되는지, 아니면 무엇을 확인할지" 알려 주는 진단. → 새 구조에서 진단을 어디에 둘지는 **미정** (8장 질문 1).

### 3.3 펌웨어 `firmware/node/` — USB 시리얼 버전 (2026-10-23) → P2에서 WiFi 버전으로 (3.6)
- 사용자가 (2026-10-23 당시) 단 센서: **DHT11 1개(온습도 A 자리, SHT31 납땜 전 임시)** — 2026-10-24 SHT31 A·B로 바뀜(3.6), **토양 2개**, **로드셀+HX711(DT26·SCK27)**. 사용자가 준 로드셀 시험 코드는 bogde HX711 라이브러리.
- `node.ino` + `config.h`(센서 켜고 끄기·핀). 규약은 지시서 4장 그대로, 시리얼 JSON + 명령(info·status·tare·cal·soilcal·flow·interval·id·reboot·pump·water·stop). 펌프 안전(15초·쿨다운·50/300mL·12V·누수·scale_dead) 포함. `flowcal`은 아직(P2).
- 규약 밖 추가: data `weight_raw`(보정 전 원시값), info `sensor_a`·`*_present`(미설치 센서 구분). 웹 홈이 "미설치"·"raw … · 보정 전"으로 보여 준다.
- 이 노트북 arduino-cli로 **컴파일 통과**. 같은 형식의 가짜 줄(socket://)로 서버·웹 표시 확인. **사용자 말(2026-10-23): 실물 보드에 올려 USB로 연결·센서값까지 됐다** (AI는 직접 보지 못함). WiFi는 아직 안 씀 → P2에서 처음 확인. (DHT11은 2026-10-24에 SHT31 A·B로 바뀌어 DHT_PIN 확인은 필요 없어짐)
- 서버: mock 모드 기록은 `data/mock/`·`logs/mock/`에 따로 저장하도록 바꿈 (실제 기록과 섞이지 않게).

### 3.5 Supabase `supabase/` — P1 완료 (2026-10-23)

## 5. 제안 설계 (P1·P2에서 확정)

> 확정된 표·함수·권한은 **`supabase/schema.sql`이 기준**이다 (아래는 처음 제안이라 열 이름이 조금 다르다: readings는 `extra jsonb`, events는 `t`·`ev`·`payload`). 명령은 ESP32가 Realtime 알림을 받고 `rpc/claim_command`로 가져간다 (3.6).

### 5.1 Supabase 표
| 표 | 쓰는 쪽 → 읽는 쪽 | 내용 |
|---|---|---|
| `readings` | ESP32 → 웹 | 주기 측정값 한 줄 = 한 행. 열은 지시서 4.2 `data` 키 그대로 (`node, seq, temp_a, rh_a, temp_b, rh_b, soil_a_mv, soil_a, soil_b_mv, soil_b, hx_ok, weight_g, weight_sd, v12, leak, pump, rssi`) + `created_at`(서버 시각) + `raw jsonb` |
| `events` | ESP32 → 웹 | `boot`, `pump_on`, `pump_off`, `refused`, `info` 등 (`node, kind, payload jsonb, created_at`) |
| `nodes` | ESP32 → 웹 | 구역별 마지막 상태·보정값(`info` 내용), `last_seen`. ESP32가 upsert |
| `commands` | 웹 → ESP32 → 웹 | `id, node, cmd('water 10' 같은 지시서 4.3 명령 문자열), status(pending→sent→done/failed/expired), result jsonb(ack), created_at, done_at` |
| `diagnostics` | 진단 서버 → 웹 | (P6 선택) 지시서 6.2 형식 |

### 5.2 명령 흐름과 안전
1. 웹이 `commands`에 `pending`으로 넣는다 (허용 명령만: water, stop, tare, cal, soilcal, flow, interval, info, status, reboot, flowcal — DB CHECK 제약으로 막는다).
2. ESP32가 1~2초마다 자기 구역의 `pending`을 가져가 `sent`로 바꾸고 실행, ack를 `result`에 넣고 `done`/`failed`.
3. **만든 지 10초가 넘은 명령은 실행하지 않고 `expired`** (ESP32가 꺼져 있다 켜졌을 때 오래된 급수 명령이 실행되는 사고 방지).
4. ESP32 안전(최종 판단, SYS-02 유지): 부팅 시 펌프 OFF, 1회 최대 15초 후 스스로 끔, 12V 없음·누수면 거부·즉시 끔, 끈 뒤 3초 쉬기, **하루 300mL 한도와 유량 보정 확인도 ESP32가** (하루는 NTP 시각 기준).
5. `stop`은 다른 명령보다 먼저 처리.
6. 로그인이 없으므로 anon key로 누구나 `commands`에 넣을 수 있다. 쓰기 권한은 RLS로 최소화하고, ESP32가 쓰는 표(readings 등)는 **기기 비밀값 헤더**(예: `x-device-key`)를 RLS 조건으로 확인하는 방식을 검토한다.

### 5.3 무료 등급에서 주의할 것 (P1에서 최신 정책 확인)
- 5초 × 3구역 ≈ 하루 5만 행 → 무료 DB 용량(약 500MB)을 몇 주 만에 채울 수 있다 → **보관 기간(예: 14일) 자동 삭제** 또는 주기 늘리기.
- 무료 프로젝트는 오래 쓰지 않으면 일시정지될 수 있다 (정책 확인 필요).
- ESP32 HTTPS: 처음에는 `WiFiClientSecure::setInsecure()`로 단순하게, 이후 루트 인증서 고정 검토.

### 5.4 하드웨어 (지시서 1.3 그대로 가정 — 8장 질문 3으로 확인)
SHT31 A 0x44 / B 0x45 (SDA21·SCL22), SEN0193 A GPIO32 / B GPIO33, HX711 DT26·SCK27, 펌프 DFR0457 GPIO25(+10kΩ 풀다운), 12V 감지 GPIO34(47k/10k), 누수 GPIO35(선택). 보정값은 NVS 이름공간 `chamgap`.

## 7. 지킬 관례

- **웹**: TS strict, `any` 금지. `src/components/react-bits/`·`src/components/ui/` 원본은 고치지 않고 `src/components/fx/` 래퍼를 쓴다 (꼭 고치면 `// MODIFIED:` 주석). 모든 래퍼는 움직임 줄이기 지원. 상태는 색+글자+아이콘(UI-05). **모두 정지 버튼은 모든 화면에 항상, 확인 창 없이. 급수는 1초 길게 누르기로만.** 진단 문구를 웹에서 지어내지 않는다 (진단 서버가 주는 것만 표시).
- **서버**: ruff 기본 규칙, pytest, 시간은 `Clock` 주입(테스트에서 건너뛰기).
- **펌웨어**: 비밀값(WiFi 비밀번호, Supabase 키, 기기 비밀값)은 `secrets.h`에만, 저장소에는 `secrets.example.h`만. 시리얼(115200, 한 줄 JSON) 출력은 계속 유지해 USB로도 볼 수 있게.
- **웹 환경변수**: `web/.env.local` (git 제외), Vercel에는 프로젝트 설정의 Environment Variables로.
- 단계가 끝나면 이 문서 3장·4장을 갱신한다.
