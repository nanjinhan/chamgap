# 참값(CHAMGAP) 센서 진단 시스템 — 요구사항지시서

| 항목 | 내용 |
|---|---|
| 문서 버전 | **v2.0 (2026-10-23)** — v1.0은 `docs/archive/01_requirements_v1.0.md` |
| 대상 | ESP32 펌웨어, Supabase(클라우드 DB), 웹앱, (선택) 진단 서버 |
| 기준 설계 | 3구역 시험장 제작 설계도 v0.8.1 (배선·핀 번호) |
| 이 문서의 역할 | 프로그램들이 서로 주고받는 **약속**의 기준. 코드와 이 문서가 다르면 이 문서를 먼저 고친 뒤 코드를 고친다 |

요구사항 번호 규칙: `SYS` 전체, `FW` ESP32 펌웨어, `COM` 통신 규약, `CLD` Supabase, `SRV` 진단 서버, `DX` 진단, `SAFE` 안전, `UI` 웹앱, `NFR` 비기능. 각 항목의 **필수/권장/선택**을 지킨다.

## 변경 이력

| 버전 | 바뀐 것 |
|---|---|
| v1.0 | ESP32 ─USB·로컬 MQTT─▶ 노트북 브리지 서버 ─▶ 웹앱. 같은 WiFi 안에서만, 인터넷 공개·로그인 제외 |
| **v2.0** | **ESP32 ─WiFi─▶ Supabase(무료) ◀─▶ 웹앱(Vercel)**. 인터넷 어디서나 접속, 로그인 없음. 급수 안전 검사를 ESP32로 옮김. 저장은 Supabase. 진단은 **선택 기능**(노트북 진단 서버가 켜져 있을 때). 웹 시험 모드 제외. 메시지 키·명령 문법은 v1.0과 같음 |

## 1. 목적과 범위

### 1.1 목적
1. **먼저**: 구역 3개(Z1·Z2·Z3)의 진짜 센서 값이 인터넷 어디서나 웹앱에 실시간으로 보이고, 웹앱에서 누른 명령(급수·정지·보정)을 ESP32가 실행해 결과가 웹에 돌아온다.
2. **다음(선택)**: 값을 보여 주는 데서 끝나지 않고, **"지금 이 값을 믿어도 되는지, 안 된다면 무엇이 문제이고 무엇을 확인해야 하는지"**를 알려 준다 (6장 진단).

### 1.2 범위
| 포함 | 선택 | 제외 |
|---|---|---|
| 센서 값 수집·표시·기록 (Supabase) | 센서 이상 진단과 확인 방법 안내 (진단 서버) | 자동 급수 스케줄 |
| 수동 급수(양 지정)와 즉시 정지 | 센서 시험 스케치 00~05 | 로그인 |
| 보정 작업 안내 (영점, 무게, 토양, 유량) | | 휴대폰 설치형 앱 |
| 인터넷 어디서나 접속 (웹앱: Vercel) | | 식물 생육 판단 |
| 하드웨어 없이 개발·시연하는 가짜 ESP32 | | 웹의 시험 모드 화면 (시험 스케치는 아두이노 IDE 시리얼 모니터로 본다) |

### 1.3 구역 하나의 구성 (설계도 기준, v1.0과 같음)
| 부품 | 수량 | ESP32 핀 | 비고 |
|---|---|---|---|
| SHT31 온습도 A (대상) | 1 | I2C SDA 21, SCL 22, 주소 0x44 | |
| SHT31 온습도 B (비교) | 1 | 같은 버스, 주소 0x45 | ADR→VIN |
| SEN0193 토양수분 A (대상) | 1 | GPIO32 (ADC1) | |
| SEN0193 토양수분 B (비교) | 1 | GPIO33 (ADC1) | |
| 로드셀 10kg + HX711 | 1 | DT 26, SCK 27 | 화분 전체 무게 |
| 연동 펌프 + DFR0457 | 1 | GPIO25 (+10kΩ 풀다운) | 12V |
| 12V 감지 분압 47k/10k | 1 | GPIO34 | 비상정지·퓨즈 감지 |
| 누수 감지 (선택) | 0~1 | GPIO35 (+풀업) | |

ADC2 핀은 WiFi와 함께 쓸 수 없으므로 아날로그 입력은 ADC1(GPIO32~39)만 쓴다 (위 배선이 이미 그렇다).

## 2. 시스템 구성

```
 [ESP32 Z1] ─┐                         ┌──────────── Supabase (무료) ────────────┐
 [ESP32 Z2] ─┼──WiFi · HTTPS/WSS──────▶│ readings · events · nodes · commands    │
 [ESP32 Z3] ─┘  값·사건 올림            │ (선택) diagnostics                       │
                명령 받아 실행 ◀────────│ Postgres + Realtime                      │
       │                               └──────────────▲──────────────────────────┘
       └─ USB 시리얼 (디버그용, 선택)                    │ 실시간 구독 · 명령 넣기
                                                       │
                                  [웹앱 (React, Vercel)] ◀── 폰·노트북 어디서나
                                                       │
                     (선택) [진단 서버 (Python, 노트북)] ── 값을 읽어 진단을 기록
```

| ID | 요구사항 | 구분 |
|---|---|---|
| SYS-01 | ESP32와 웹앱은 **Supabase 표를 통해서만** 주고받는다. 서로 직접 연결하지 않는다 | 필수 |
| SYS-02 | 펌프를 켜도 되는지의 **최종 판단은 ESP32**가 한다. 급수 안전 검사(7장 SAFE-03)는 ESP32가 하고, 웹은 요청과 사전 안내만 한다 | 필수 |
| SYS-03 | 메시지 내용(키 이름·명령 문법)은 v1.0 4장과 같다. Supabase 표의 열 이름은 메시지 키 이름과 같다. ESP32는 USB 시리얼에도 같은 줄을 계속 출력한다 | 필수 |
| SYS-04 | 하드웨어 없이 개발할 수 있도록 **가짜 ESP32**(기존 서버의 mock 재사용)가 실제 펌웨어와 똑같이 Supabase에 쓰고 명령에 응답한다. 고장 상황을 골라 재현할 수 있다 | 필수 |
| SYS-05 | **무료 등급**(Supabase Free, Vercel Hobby) 안에서 동작한다. 로그인은 없다 | 필수 |
| SYS-06 | 진단은 **진단 서버가 켜져 있을 때만** 붙는다. 웹앱은 진단을 만들지 않고 진단 서버가 준 결과만 보여 준다. 진단 서버가 꺼져 있어도 값 보기·명령은 동작한다 | 선택 |

## 3. ESP32 펌웨어 요구사항

| ID | 요구사항 | 구분 |
|---|---|---|
| FW-01 | 부팅 직후 가장 먼저 펌프 핀(GPIO25)을 LOW로 둔다 | 필수 |
| FW-02 | `sample_ms`(기본 5000ms, 범위 2000~600000)마다 측정값 1개를 Supabase `readings`에 넣고 시리얼에도 `data` 줄로 출력한다 | 필수 |
| FW-03 | 센서 하나가 고장 나도 나머지 값은 계속 보낸다. 고장 값은 `null` | 필수 |
| FW-04 | 로드셀은 막히지 않게 읽고, 최근 약 1초(10개) 평균과 표준편차를 보낸다 | 필수 |
| FW-05 | 보정값(토양 공기/물, 로드셀 영점/배율, 펌프 유량, 구역 이름, 주기)과 **오늘 급수량**은 ESP32 내부(NVS)에 저장해 전원이 꺼져도 유지한다 | 필수 |
| FW-06 | 시험 스케치(00~05)를 만들면, 거기서 저장한 보정값을 노드 펌웨어가 그대로 읽는다 (NVS 이름공간 `chamgap`) | 선택 |
| FW-07 | 시리얼 통신 속도 115200bps, 줄 끝 `\n`. 시리얼로 받은 명령도 실행한다 (USB 디버그) | 필수 |
| FW-08 | 같은 펌웨어를 세 보드에 올리고, 구역 이름은 `id z2` 명령으로 저장한다 (기본값은 `config.h`) | 권장 |
| FW-09 | WiFi(2.4GHz)가 끊기면 스스로 다시 연결한다. 끊긴 동안에도 측정·안전 동작은 계속하고, 그동안의 값은 올리지 않고 버린다 | 필수 |
| FW-10 | 명령은 **Supabase Realtime(WebSocket)**으로 받는다. 놓친 명령에 대비해 30초마다 `pending` 명령을 한 번 조회한다. Realtime을 쓸 수 없으면 2초 간격 조회로 대신한다 (1초 조회는 무료 전송량 때문에 쓰지 않는다) | 필수 |
| FW-11 | 명령은 한 번에 하나씩 실행하고, 받은 즉시 `sent`, 끝나면 ack를 `result`에 넣고 `done`/`failed`로 바꾼다. `stop`은 다른 명령보다 먼저 처리한다 | 필수 |
| FW-12 | 시각은 NTP(한국 시간)로 맞춘다. "오늘"(하루 급수 한도)은 한국 날짜 기준이며, 시각을 모르는 동안은 부팅 후 누적으로 센다 | 필수 |
| FW-13 | WiFi 이름·비밀번호, Supabase 주소·키, 기기 키는 `secrets.h`에만 둔다. 저장소에는 `secrets.example.h`만 넣는다 | 필수 |
| FW-14 | HTTPS로 Supabase에 접속한다. 처음에는 인증서 확인 없이(`setInsecure`) 시작하고, 이후 루트 인증서 고정을 권장한다 | 필수 |

## 4. 통신 규약

### 4.1 공통 형식 (v1.0과 같음)
| ID | 요구사항 | 구분 |
|---|---|---|
| COM-01 | 메시지 하나 = JSON 객체 하나. 시리얼에서는 한 줄, `{`로 시작 | 필수 |
| COM-02 | 시리얼에서 `#`로 시작하는 줄은 사람용 메모 | 필수 |
| COM-04 | 명령은 공백으로 나눈 **텍스트 한 줄**. 대소문자 구분 없음 (시리얼은 끝에 `\n`) | 필수 |
| COM-05 | 모든 JSON 메시지에는 `t`(종류), `node`(구역), `ms`(ESP32 부팅 후 ms)가 있다 | 필수 |
| COM-06 | 값이 없거나 고장이면 키를 빼지 않고 `null`을 넣는다 | 필수 |
| COM-07 | 참/거짓은 `1`/`0`으로 보낸다 | 필수 |
| COM-08 | 시간 기준은 Supabase가 붙이는 `created_at`이다 (ESP32 `ms`는 부팅 후 시간) | 필수 |
| COM-09 | 받는 쪽은 모르는 키가 와도 오류를 내지 않는다. 표에 없는 키는 `extra`(jsonb)에 보관한다 | 필수 |

### 4.2 메시지 종류: ESP32 → (Supabase · 시리얼)

#### `data` — 주기 측정값 → `readings` 표
```json
{"t":"data","node":"Z1","ms":20111,"seq":4,
 "sht_a_ok":1,"temp_a":23.40,"rh_a":45.10,
 "sht_b_ok":1,"temp_b":23.60,"rh_b":44.80,
 "soil_a_mv":2400,"soil_a":0.077,"soil_b_mv":1800,"soil_b":0.538,
 "hx_ok":1,"weight_g":500.0,"weight_sd":0.10,
 "v12":12.00,"leak":null,"pump":1,"rssi":-55}
```
| 키 | 형 | 단위 | 뜻 | null 일 때 |
|---|---|---|---|---|
| `seq` | int | | 1부터 1씩 증가. 재부팅하면 1로 | — |
| `sht_a_ok` / `sht_b_ok` | 0/1 | | 이번 읽기 성공 | — |
| `temp_a` / `temp_b` | float | °C | 공기 온도 | 읽기 실패 |
| `rh_a` / `rh_b` | float | %RH | 공기 습도 | 읽기 실패 |
| `soil_a_mv` / `soil_b_mv` | int | mV | 토양 센서 원시 전압 | — |
| `soil_a` / `soil_b` | float | 0~1 | 0=공기, 1=물 (보정값 기준) | 선 빠짐·단락 의심, 보정값 이상 |
| `hx_ok` | 0/1 | | 최근 1초 안에 HX711 응답 | — |
| `weight_g` | float | g | 화분 전체 무게 (영점 기준) | HX711 응답 없음, 보정 전 |
| `weight_sd` | float | g | 최근 약 1초 흔들림 | 위와 같음 |
| `v12` | float | V | 분기 퓨즈 뒤 12V | 12V 감지 사용 안 함 |
| `leak` | 0/1 | | 누수 감지 | 누수 센서 없음 |
| `pump` | 0/1 | | 지금 펌프 켜짐 | — |
| `rssi` | int | dBm | WiFi 세기 | WiFi 연결 안 됨 |

#### `evt` — 사건 → `events` 표
| `ev` | 추가 키 | 언제 |
|---|---|---|
| `boot` | `fw`, `reset`(`esp_reset_reason()` 번호), `sht_a`, `sht_b` | 전원·재시작 직후 1번 |
| `pump_on` | `dur`(ms), `ml`(급수량, `water`가 아니면 null) | 펌프 켜짐 |
| `pump_off` | `reason`, `dur`, `ran`(실제 켜진 ms), `ml`(**실제 켜진 시간 기준** mL, 유량 보정 전이면 null) | 펌프 꺼짐 |
| `refused` | `reason`, `dur`, `ml` | 펌프 요청 거부 |

`reason` 값:
| 값 | 뜻 |
|---|---|
| `done` | 정해진 시간 끝 |
| `stop` | 정지 명령 |
| `no_12v` | 12V 없음 (비상정지 눌림·퓨즈·선 빠짐) |
| `leak` | 누수 감지 |
| `reboot` | 재시작 명령 |
| `already_on` | 이미 켜져 있음 (거부) |
| `bad_ms` | 시간 범위 밖 (50~15000ms) (거부) |
| `cooldown` | 꺼진 지 3초 안 됨 (거부) |
| `bad_ml` | 1회 급수량 범위 밖 (1~50mL) (거부) — v2.0 추가 |
| `daily_limit` | 오늘 급수 한도 초과 (300mL) (거부) — v2.0 추가 |
| `flow_uncal` | 유량 보정 전이라 mL 급수 불가 (거부) — v2.0 추가 |
| `scale_dead` | 무게 센서 응답 없음 (거부) — v2.0 추가 |

#### `ack` — 명령 응답 → `commands.result` (+ 시리얼)
```json
{"t":"ack","node":"Z1","ms":15111,"cmd":"cal","ok":1,"msg":""}
```
명령마다 **정확히 1개**를 보낸다 (`status`, `info`도 각각 data·info를 보낸 뒤 ack 1개). `ok=0`이면 `msg`에 이유(위 `reason` 값 또는 짧은 영문)가 있다. 결과 값이 있는 명령은 ack에 키를 더한다 (예: `flowcal`의 `before_g`, `after_g`, `delta_g`).

#### `info` — 설정·보정 상태 → `nodes.info` (+ `events`)
부팅 직후, WiFi 연결 직후, 보정·설정 명령이 성공한 뒤, `info` 명령을 받았을 때 보낸다.
```json
{"t":"info","node":"Z1","ms":200,"fw":"node-2.0","sample_ms":5000,
 "soil_a_cal":0,"soil_b_cal":0,"soil_a_air":2500,"soil_a_wet":1200,"soil_b_air":2500,"soil_b_wet":1200,
 "lc_cal":0,"lc_offset":0,"lc_scale":0.0000,"pump_mlps":0.000,
 "v12_sense":1,"leak_sensor":0,"day_ml":0.0,"day_limit_ml":300,"max_ml":50}
```
v2.0: 토양 보정 여부를 채널별(`soil_a_cal`, `soil_b_cal`)로 보내고, 오늘 급수량과 한도를 함께 보낸다.

### 4.3 명령: 웹 → `commands` 표 → ESP32 (시리얼로도 같은 문법)
| 명령 | 예 | 하는 일 | 응답 |
|---|---|---|---|
| `help` | | 명령 목록 | ack |
| `status` | | 즉시 `data` 1개 | data + ack |
| `info` | | 설정·보정 상태 | info + ack |
| `water <mL>` | `water 10` | 안전 검사(SAFE-03) 후 저장된 유량으로 환산해 켬 | evt + ack |
| `stop` | | 즉시 끔 | evt(켜져 있었으면) + ack |
| `tare` | | 빈 판 영점 (약 2초) | ack |
| `cal <g>` | `cal 500` | 아는 무게로 배율 보정 (tare 먼저) | ack |
| `soilcal <a\|b> <air\|wet>` | `soilcal a air` | 토양 보정값 저장 | ack |
| `flowcal <ms>` | `flowcal 10000` | **유량 측정용 펌프 실행**: 안정 무게 → ms 동안 펌프 → 최대 60초 안정 대기 → 무게 증가 (저장은 안 함) | evt + ack(`before_g`,`after_g`,`delta_g`) |

### 4.4 Supabase 표
| 표 | 쓰는 쪽 | 읽는 쪽 | 열 (요지) |
|---|---|---|---|
| `readings` | ESP32 | 웹, 진단 서버 | `id`, `created_at`, `node`, `ms`, 4.2 `data`의 키 전부, `extra jsonb` |
| `events` | ESP32, 웹(메모만), 진단 서버 | 웹, 진단 서버 | `id`, `created_at`, `node`, `t`(`evt`·`info`·`mark`·`diag_on`·`diag_off`·`water_result`), `ev`, `payload jsonb` |
| `nodes` | ESP32 | 웹, 진단 서버 | `node`(기본 키), `updated_at`, `last_seen`, `fw`, `info jsonb`, `pump`(0/1), `day_ml` |
| `commands` | 웹(넣기), ESP32(상태 바꾸기) | 웹, ESP32 | `id`, `created_at`, `node`, `cmd`, `status`(`pending`→`sent`→`done`/`failed`/`expired`), `picked_at`, `done_at`, `result jsonb` |
| `diagnostics` | 진단 서버 | 웹 | (선택) 6.2 형식 그대로, 구역·코드·센서별 1행. 지금 활성인 것만 |
| `service_status` | 진단 서버 | 웹 | (선택) `name`, `updated_at` — 진단 서버가 켜져 있는지 |

- 웹은 Realtime으로 `readings`·`events` 새 행, `commands`·`nodes`·`diagnostics` 변경을 구독한다.
- 구역 온라인 여부는 웹이 정한다: 마지막 `readings`가 `3 × sample_ms`(최소 15초)보다 오래되면 오프라인. 기기 시계 차이는 받은 행의 `created_at`으로 보정한다 (UI-11).

| UI-13 | 진단 서버가 꺼져 있으면 진단 자리에 그 사실을 알리고, 값·급수·보정은 그대로 쓸 수 있게 한다 | 필수 |

## 10. 단계별 진행과 검수

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| P0 | 이 문서 v2.0 | 사용자 확인 |
| P1 | Supabase 준비 (`supabase/schema.sql`) | 사용자 프로젝트에 표가 생기고, anon key로 읽기·명령 넣기는 되고 기기 키 없이 `readings` 쓰기는 거부됨 |
| P2 | ESP32 노드 펌웨어 | 컴파일 통과. 실물이 있으면 Z1 값이 Supabase `readings`에 5초마다, 명령의 `status`가 `done`으로 바뀜 |
| P3 | 가짜 ESP32 → Supabase | 하드웨어 없이 3구역 값이 Supabase에 들어가고, 명령에 펌웨어와 같은 ack가 돌아옴. 고장 시나리오 재현 |
| P4 | 웹 데이터 계층 Supabase로 교체 | 웹에서 3구역 값이 실시간으로 바뀌고, 명령 결과가 돌아옴. 연결을 끊었다 붙이면 다시 연결됨 |
| P5 | 웹 화면 | 와이어프레임 화면 전부. 급수 → 섬 진행 표시 → 결과, 보정 마법사가 ack 기반으로 진행 |
| P6 | (선택) 진단 서버 | 6.4 시나리오마다 해당 진단이 웹에 뜸 |
| P7 | Vercel 배포 + 실물 | 폰 LTE로 웹 주소 접속. Z1 하나로 급수 → 무게 증가 → 수분 상승까지 화면에서 확인, 이어서 3구역 |
