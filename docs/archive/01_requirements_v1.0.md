# 참값(CHAMGAP) 센서 진단 시스템 — 요구사항지시서

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 (2026-10-23) |
| 대상 | ESP32 펌웨어, 노트북 브리지 서버, 웹앱 |
| 기준 설계 | 3구역 시험장 제작 설계도 v0.8.1 (배선·핀 번호) |
| 이 문서의 역할 | 세 프로그램이 서로 주고받는 **약속**의 기준. 코드와 이 문서가 다르면 이 문서를 먼저 고친 뒤 코드를 고친다 |

요구사항 번호 규칙: `SYS` 전체, `FW` ESP32 펌웨어, `COM` 통신 규약, `SRV` 브리지 서버, `DX` 진단, `SAFE` 안전, `UI` 웹앱, `NFR` 비기능. 각 항목의 **필수/권장**을 지킨다.

---

## 1. 목적과 범위

### 1.1 목적
구역 3개(Z1·Z2·Z3)의 센서 값을 실시간으로 보여주는 데서 끝나지 않고, **"지금 이 값을 믿어도 되는지, 안 된다면 무엇이 문제이고 무엇을 확인해야 하는지"**를 웹앱에서 알려준다.

### 1.2 범위
| 포함 | 제외 |
|---|---|
| 센서 값 수집·표시·기록 | 자동 급수 스케줄 (2차) |
| 센서 이상 진단과 확인 방법 안내 | 인터넷 공개, 로그인 |
| 수동 급수(양 지정)와 즉시 정지 | 휴대폰 설치형 앱 |
| 보정 작업 안내 (영점, 무게, 토양, 유량) | 식물 생육 판단 |

### 1.3 구역 하나의 구성 (설계도 기준)
| 부품 | 수량 | ESP32 핀 | 비고 |
|---|---|---|---|
| SHT31 온습도 A (대상) | 1 | I2C SDA 21, SCL 22, 주소 0x44 | |
| SHT31 온습도 B (비교) | 1 | 같은 버스, 주소 0x45 | ADR→VIN |
| SEN0193 토양수분 A (대상) | 1 | GPIO32 (ADC1) | |
| SEN0193 토양수분 B (비교) | 1 | GPIO33 (ADC1) | |
| 로드셀 10kg + HX711 | 1 | DT 26, SCK 27 | 화분 전체 무게 |
| 연동 펌프 + DFR0457 | 1 | GPIO25 (+10kΩ 풀다운) | 12V |
| 12V 감지 분압 47k/10k | 1 | GPIO34 | 비상정지·퓨즈 감지 |
| 누수 감지 (선택) | 0~1 | GPIO35 (+풀업) | |

## 2. 시스템 구성

```
 [ESP32 Z1] ─┐  USB 시리얼 (1단계)  또는  WiFi MQTT (2단계)
 [ESP32 Z2] ─┼──────────────────────────────▶ [노트북 브리지 서버 (Python)]
 [ESP32 Z3] ─┘  ◀── 텍스트 명령 ──────────────        │  진단 · 기록 · 안전 검사
                                                     │  REST + WebSocket
                                                     ▼
                                   [웹앱 (React)]  노트북 브라우저 / 같은 WiFi 폰 브라우저
```

| ID | 요구사항 | 구분 |
|---|---|---|
| SYS-01 | 판단(진단)은 **브리지 서버 한 곳**에서만 한다. 웹앱은 서버가 준 결과를 보여주기만 한다 | 필수 |
| SYS-02 | 펌프를 켜도 되는지의 **최종 판단은 ESP32**가 한다. 서버와 웹앱은 요청만 한다 | 필수 |
| SYS-03 | 1단계(USB)와 2단계(MQTT)에서 메시지 내용은 **완전히 같다**. 서버는 연결 방식만 바꾼다 | 필수 |
| SYS-04 | 하드웨어 없이도 개발할 수 있도록 서버에 **모의(mock) 모드**를 둔다 | 필수 |
| SYS-05 | 노트북 한 대가 브리지 서버와 웹앱을 함께 띄운다. 외부 인터넷 없이 동작한다 | 필수 |

## 3. ESP32 펌웨어 요구사항

| ID | 요구사항 | 구분 |
|---|---|---|
| FW-01 | 부팅 직후 가장 먼저 펌프 핀(GPIO25)을 LOW로 둔다 | 필수 |
| FW-02 | `sample_ms`(기본 5000ms)마다 `data` 메시지를 1개 보낸다 | 필수 |
| FW-03 | 센서 하나가 고장 나도 나머지 값은 계속 보낸다. 고장 값은 `null` | 필수 |
| FW-04 | 로드셀은 막히지 않게 읽고, 최근 약 1초(10개) 평균과 표준편차를 보낸다 | 필수 |
| FW-05 | 보정값(토양 공기/물, 로드셀 영점/배율, 펌프 유량, 구역 이름, 주기)은 ESP32 내부(NVS)에 저장해 전원이 꺼져도 유지한다 | 필수 |
| FW-06 | 시험 스케치(00~05)에서 저장한 보정값을 노드 펌웨어가 그대로 읽는다 (NVS 이름공간 `chamgap`) | 필수 |
| FW-07 | 시리얼 통신 속도 115200bps, 줄 끝 `\n` | 필수 |
| FW-08 | 같은 펌웨어를 세 보드에 올리고, 구역 이름은 `id z2` 명령으로 저장한다 | 권장 |
| FW-09 | MQTT 사용은 설정값(`USE_MQTT`) 하나로 켜고 끈다. 켜도 시리얼 출력은 계속한다 | 필수 |

### 3.1 NVS 저장 키 (이름공간 `chamgap`)
| 키 | 형 | 내용 | 저장하는 곳 |
|---|---|---|---|
| `soilA_air`, `soilA_wet`, `soilB_air`, `soilB_wet` | int (mV) | 토양 보정 | 02_soil, 노드 `soilcal` |
| `lc_off` | long | 로드셀 영점 raw | 03_loadcell, 노드 `tare` |
| `lc_scale` | float | raw/g | 03_loadcell, 노드 `cal` |
| `pump_mlps` | float | 초당 mL | 05_pump, 노드 `flow` |
| `sample_ms` | ulong | 보내는 주기 | 노드 `interval` |
| `node_id` | string | 구역 이름 (Z1) | 노드 `id` |

## 4. 통신 규약 (가장 중요)

### 4.1 공통 형식
| ID | 요구사항 | 구분 |
|---|---|---|
| COM-01 | ESP32 → 서버: **한 줄 = JSON 객체 하나**. `{`로 시작 | 필수 |
| COM-02 | `#`로 시작하는 줄은 사람용 메모. 서버는 로그로만 보여주고 해석하지 않는다 | 필수 |
| COM-03 | 그 외 줄(부팅 로그 등)도 무시하되 기록 화면에는 회색으로 보여준다 | 권장 |
| COM-04 | 서버 → ESP32: 공백으로 나눈 **텍스트 명령 한 줄**. 대소문자 구분 없음. 끝은 `\n` | 필수 |
| COM-05 | 모든 JSON 메시지에는 `t`(종류), `node`(구역), `ms`(ESP32 부팅 후 ms)가 있다. 시험 스케치는 `node`가 없을 수 있다 | 필수 |
| COM-06 | 값이 없거나 고장이면 키를 빼지 않고 `null`을 넣는다 | 필수 |
| COM-07 | 참/거짓은 `1`/`0`으로 보낸다 | 필수 |
| COM-08 | 서버는 받은 메시지에 `pc_time`(ISO 8601, ms까지)과 `src`(포트 이름 또는 `mqtt`)를 붙여 저장한다. ESP32에는 시계가 없으므로 **시간 기준은 pc_time** | 필수 |
| COM-09 | 서버는 모르는 키가 와도 오류를 내지 않고 그대로 저장한다 (앞으로 키가 늘어날 수 있음) | 필수 |

### 4.2 메시지 종류: ESP32 → 서버

#### `data` — 주기 측정값
```json
{"t":"data","node":"Z1","ms":20111,"seq":4,
 "sht_a_ok":1,"temp_a":23.40,"rh_a":45.10,
 "sht_b_ok":1,"temp_b":23.60,"rh_b":44.80,
 "soil_a_mv":2400,"soil_a":0.077,"soil_b_mv":1800,"soil_b":0.538,
 "hx_ok":1,"weight_g":500.0,"weight_sd":0.10,
 "v12":12.00,"leak":null,"pump":1,"rssi":-55}
```
| 키 | 형 | 단위 | 뜻 | null 일 때 |
|---|---|---|---|---|
| `seq` | int | | 1부터 1씩 증가. 재부팅하면 1로 | — |
| `sht_a_ok` / `sht_b_ok` | 0/1 | | 이번 읽기 성공 | — |
| `temp_a` / `temp_b` | float | °C | 공기 온도 | 읽기 실패 |
| `rh_a` / `rh_b` | float | %RH | 공기 습도 | 읽기 실패 |
| `soil_a_mv` / `soil_b_mv` | int | mV | 토양 센서 원시 전압 | — |
| `soil_a` / `soil_b` | float | 0~1 | 0=공기, 1=물 (보정값 기준) | 선 빠짐·단락 의심, 보정값 이상 |
| `hx_ok` | 0/1 | | 최근 1초 안에 HX711 응답 | — |
| `weight_g` | float | g | 화분 전체 무게 (영점 기준) | HX711 응답 없음, 보정 전 |
| `weight_sd` | float | g | 최근 약 1초 흔들림 | 위와 같음 |
| `v12` | float | V | 분기 퓨즈 뒤 12V | 12V 감지 사용 안 함 |
| `leak` | 0/1 | | 누수 감지 | 누수 센서 없음 |
| `pump` | 0/1 | | 지금 펌프 켜짐 | — |
| `rssi` | int | dBm | WiFi 세기 (MQTT 모드에서만 있음) | — |

#### `evt` — 사건
| `ev` | 추가 키 | 언제 |
|---|---|---|
| `boot` | `fw`, `reset`(재시작 원인 번호), `sht_a`, `sht_b` | 전원·재시작 직후 1번 |
| `pump_on` | `dur`(ms), `ml`(유량 보정 시 예상 mL, 아니면 null) | 펌프 켜짐 |
| `pump_off` | `reason`, `dur`, `ran`(실제 켜진 ms), `ml` | 펌프 꺼짐 |
| `refused` | `reason`, `dur`, `ml` | 펌프 요청 거부 |

`reason` 값:
| 값 | 뜻 |
|---|---|
| `done` | 정해진 시간 끝 |
| `stop` | 정지 명령 |
| `no_12v` | 12V 없음 (비상정지 눌림·퓨즈·선 빠짐) |
| `leak` | 누수 감지 |
| `reboot` | 재시작 명령 |
| `already_on` | 이미 켜져 있음 (거부) |
| `bad_ms` | 시간 범위 밖 (50~15000ms) (거부) |
| `cooldown` | 꺼진 지 3초 안 됨 (거부) |

#### `ack` — 명령 응답
```json
{"t":"ack","node":"Z1","ms":15111,"cmd":"cal","ok":1,"msg":""}
```
명령마다 정확히 1개를 보낸다. `ok=0`이면 `msg`에 이유가 있다.

#### `info` — 설정·보정 상태
부팅 직후, MQTT 연결 직후, `info` 명령을 받았을 때 보낸다.
```json
{"t":"info","node":"Z1","ms":200,"fw":"node-0.1","sample_ms":5000,
 "soil_cal":0,"soil_a_air":2500,"soil_a_wet":1200,"soil_b_air":2500,"soil_b_wet":1200,
 "lc_cal":0,"lc_offset":0,"lc_scale":0.0000,"pump_mlps":0.000,
 "v12_sense":1,"leak_sensor":0,"mqtt":0}
```

#### 시험 스케치 메시지 (00~05)
`node` 없이 `t`가 `i2c`, `sht`, `soil`, `soilcal`, `lc`, `lccal`, `pwr`, `pump`, `pumpcal`, `evt`인 메시지가 온다. 서버는 진단하지 않고 **"시험 모드"** 화면에 키=값으로 보여주고 기록만 한다.

### 4.3 명령: 서버 → ESP32 (노드 펌웨어)
| 명령 | 예 | 하는 일 | 응답 |
|---|---|---|---|
| `help` | | 명령 목록 | ack |
| `status` | | 즉시 `data` 1개 | data |
| `info` | | 설정·보정 상태 | info |
| `pump <ms>` | `pump 2000` | 50~15000ms 펌프 켬 | evt + ack |
| `water <mL>` | `water 10` | 저장된 유량으로 환산해 켬 | evt + ack |
| `stop` | | 즉시 끔 | evt + ack |
| `tare` | | 빈 판 영점 (약 2초 걸림) | ack |
| `cal <g>` | `cal 500` | 아는 무게로 배율 보정 (tare 먼저) | ack |
| `soilcal <a\|b> <air\|wet>` | `soilcal a air` | 토양 보정값 저장 | ack |
| `flow <ms> <g>` | `flow 10000 23.5` | 유량 저장 (ms 동안 받은 물 g) | ack |
| `interval <ms>` | `interval 2000` | 보내는 주기 (500~600000) | ack |
| `id <이름>` | `id z2` | 구역 이름 저장 (재시작 후 적용) | ack |
| `reboot` | | 재시작 | ack |

| ID | 요구사항 | 구분 |
|---|---|---|
| COM-10 | 서버는 구역마다 **한 번에 명령 하나**만 보내고, ack를 기다린다 (시간 제한 3초, `tare`·`cal`은 5초). 시간 초과면 실패로 처리한다 | 필수 |
| COM-11 | `stop`은 대기열을 건너뛰고 즉시 보낸다 | 필수 |

### 4.4 MQTT (2단계)
| 토픽 | 방향 | 내용 |
|---|---|---|
| `chamgap/<구역>/data` | ESP32 → | data JSON |
| `chamgap/<구역>/evt` | ESP32 → | evt JSON |
| `chamgap/<구역>/ack` | ESP32 → | ack JSON |
| `chamgap/<구역>/info` | ESP32 → | info JSON |
| `chamgap/<구역>/online` | ESP32 → (retained) | `1` 접속 / `0` 끊김 (브로커 유언 메시지) |
| `chamgap/<구역>/cmd` | → ESP32 | 텍스트 명령 |

브로커: 노트북의 Mosquitto, 포트 1883, 같은 WiFi 안에서만.

## 5. 브리지 서버 요구사항

| ID | 요구사항 | 구분 |
|---|---|---|
| SRV-01 | Python 3.11 이상, FastAPI + Uvicorn | 필수 |
| SRV-02 | 연결 방식 3가지: `serial`(포트 1~3개), `mqtt`, `mock`. 실행 옵션이나 설정 파일로 고른다 | 필수 |
| SRV-03 | serial: 포트를 지정하지 않으면 ESP32 USB 칩(CP210x 0x10C4, CH340 0x1A86, ESP32 내장 0x303A, FTDI 0x0403)을 자동으로 찾는다 | 필수 |
| SRV-04 | serial: 케이블이 빠지면 2초마다 다시 연결하고, 이 상태를 웹앱에 알린다 | 필수 |
| SRV-05 | mock: 구역 3개의 그럴듯한 값을 만들고, 명령에 펌웨어와 똑같이 응답한다. 고장 상황을 골라 재현할 수 있다 (6.4절) | 필수 |
| SRV-06 | 구역 이름은 메시지의 `node`로 알아내고, 구역 → 연결 경로를 기억한다 | 필수 |
| SRV-07 | 모든 메시지를 `logs/<날짜>/all.jsonl`에 그대로, `data`는 SQLite에도 저장한다 | 필수 |
| SRV-08 | 최근 24시간 값을 그래프용으로 제공한다 (평균으로 묶기: 1분/5분/15분) | 필수 |
| SRV-09 | 메모(`mark`)를 기록에 남길 수 있다. 예: "Z1 물 20mL 줌" | 권장 |
| SRV-10 | CSV 내보내기 (구역·기간 선택) | 권장 |
| SRV-11 | 같은 WiFi의 폰에서 접속할 수 있도록 `0.0.0.0`으로 열고, 시작할 때 접속 주소를 화면에 보여준다 | 필수 |

### 5.1 REST API
| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/state` | 전체 현재 상태 (5.3절 형식) |
| GET | `/api/nodes/{node}` | 한 구역 상태 + 최근 메시지 |
| GET | `/api/history?node=Z1&metric=temp_a,temp_b&minutes=60&bucket=60` | 그래프용 시계열 |
| GET | `/api/events?node=Z1&limit=100` | 사건·ack·진단 변화 기록 |
| GET | `/api/diagnostics` | 지금 활성인 진단 전부 |
| POST | `/api/nodes/{node}/water` `{"ml":10}` | 급수 요청 (6.3절 검사 통과 시) |
| POST | `/api/nodes/{node}/stop` | 정지 |
| POST | `/api/stop-all` | 모든 구역 정지 |
| POST | `/api/nodes/{node}/command` `{"cmd":"tare"}` | 그 밖의 명령 (허용 목록만) |
| POST | `/api/mark` `{"node":"Z1","note":"..."}` | 메모 |
| GET | `/api/export.csv?node=Z1&from=...&to=...` | CSV |
| GET | `/api/link` | 연결 방식, 포트 상태, mock 여부 |
| GET | `/api/nodes/{node}/water/preflight?ml=10` | 급수 전 안전 검사 결과만 미리 보기 (7장 SAFE-03 항목별) |
| POST | `/api/nodes/{node}/flow-cal/run` `{"ms":10000}` | 유량 보정용 펌프 실행 + 전후 무게. 웹에서 `pump`를 보내는 유일한 길 |
| POST | `/api/raw` `{"src":"COM5","text":"air a"}` | 시험 모드 전용, 그 포트로 그대로 전송 (설정으로 끌 수 있음) |
| POST | `/api/diagnostics/reload` | `diagnostics.yaml` 다시 읽기 |
| POST | `/api/mock/scenario` `{"node":"Z2","scenario":"sht_b_dead"}` | mock 모드 전용 고장 재현 |

명령 API의 응답: `{"ok":true,"ack":{...}}` 또는 `{"ok":false,"error":"code","message":"한국어 설명"}`.

### 5.2 WebSocket `/ws`
접속하면 `snapshot`을 1번 보내고, 이후 변화가 있을 때마다 보낸다.
| `type` | 내용 |
|---|---|
| `snapshot` | `/api/state`와 같은 전체 상태 |
| `data` | 구역 하나의 새 측정값 (원본 + `pc_time`) |
| `evt` | 펌프·부팅 사건 |
| `ack` | 명령 응답 |
| `diag` | 진단 목록이 바뀐 구역의 진단 전부 |
| `link` | 연결 상태 변화 (포트 연결·끊김, 구역 온라인·오프라인) |
| `log` | `#` 메모나 해석 못한 줄 (시험 모드 화면용) |
| `test` | `node`가 없는 JSON (시험 스케치 00~05 메시지) |
| `ping` | 15초마다. 30초 동안 아무것도 못 받으면 웹앱이 다시 연결 |

### 5.3 상태 형식 (`/api/state`)
```json
{
  "server_time": "2026-10-23T16:51:02.123+09:00",
  "link": {"mode": "serial", "ports": [{"port":"COM5","connected":true,"node":"Z1"}]},
  "nodes": {
    "Z1": {
      "online": true, "last_seen": "2026-10-23T16:51:00.010+09:00",
      "status": "warn",
      "latest": { "...": "마지막 data 메시지 원본" },
      "info": { "...": "마지막 info 메시지 원본" },
      "pump": {"on": false, "last_ml": 10.0, "last_at": "...", "today_ml": 30.0},
      "sensors": {
        "sht_a":  {"status":"ok",   "value":{"temp":23.4,"rh":45.1}},
        "sht_b":  {"status":"warn", "value":{"temp":26.1,"rh":40.2}},
        "soil_a": {"status":"ok",   "value":0.53},
        "soil_b": {"status":"ok",   "value":0.51},
        "scale":  {"status":"ok",   "value":1234.5},
        "pump":   {"status":"info", "value":null},
        "power":  {"status":"ok",   "value":12.0}
      },
      "diagnostics": [ "...6.2절 형식..." ]
    }
  }
}
```
`status` 단계: `ok` < `info` < `warn` < `fault` < `offline`. 구역의 `status`는 그 구역 진단 중 가장 나쁜 단계다.

### 6.1 원칙
| ID | 요구사항 | 구분 |

| DX-01 | 진단마다 **무엇이 / 왜 의심되는지 / 무엇을 확인할지**를 한국어로 준다 | 필수 |
| DX-02 | 순간 튐으로 경고가 깜빡이지 않게, 규칙마다 **유지 시간**을 둔다. 해제는 정상 상태가 유지 시간만큼 이어진 뒤에 한다 | 필수 |
| DX-03 | 기준값은 `diagnostics.yaml` 한 파일에 두어 코드 수정 없이 바꾼다 | 필수 |
| DX-04 | 진단이 생기거나 사라질 때 `events`에 기록한다 | 필수 |
| DX-05 | 보정 전이라 생기는 문제는 `fault`가 아니라 `info`로 보여주고, 해당 보정 화면으로 가는 버튼을 준다 | 필수 |
| DX-06 | 한 원인이 여러 증상을 만들면 **원인 하나만** 크게 보여준다. 예: 구역이 오프라인이면 그 구역의 센서별 진단은 숨긴다. 12V가 없으면 "급수 안 됨" 진단은 숨긴다 | 필수 |

### 6.2 진단 형식
```json
{
  "code": "SHT_AB_DIFF",
  "node": "Z1",
  "sensor": "sht_b",

  "checks": ["A·B를 손으로 바꿔 끼워 보고 차이가 따라가는지 본다", "거치대 높이를 확인한다"],
```

### 6.3 진단 규칙 목록 (기준값은 시작값. 시험하며 조정)
| 코드 | 센서 | 조건 | 유지 | 단계 | 확인 방법 (요지) |
|---|---|---|---|---|---|
| `NODE_OFFLINE` | 구역 | 마지막 data 후 `3 × sample_ms` 이상 지남 (최소 15초) | — | offline | USB/전원, WiFi, ESP32 LED |
| `NODE_REBOOTED` | 구역 | `boot` 사건 또는 seq가 줄어듦 | 표시 5분 | info | 전원 불안정? 펌프 켤 때 재시작이면 전원 분리 확인 |
| `MSG_GAP` | 구역 | seq가 건너뜀 (10분 안 3회 이상) | — | warn | 케이블·WiFi 세기(rssi < -75) |
| `SHT_NO_RESP` | sht_a/b | `sht_*_ok = 0` | 15초 | fault | 4심 케이블, 주소(ADR), I2C 길이 |
| `SHT_RANGE` | sht_a/b | 온도 -10~60 밖 또는 습도 0~100 밖 | 즉시 | fault | 센서 손상, 물 묻음 |
| `SHT_AB_DIFF` | sht_b | \|ΔT\| > 1.0°C 또는 \|ΔRH\| > 5% | 10분 | warn | 위치·열원, A·B 바꿔 끼우기 |
| `SHT_STUCK` | sht_a/b | 30분 동안 값 변화 0.02 이하 | 30분 | warn | 센서 멈춤, 재시작 |
| `SOIL_WIRE` | soil_a/b | mV < 150 또는 > 3050 | 15초 | fault | 신호선 빠짐(낮음) / GND 빠짐·단락(높음) |
| `SOIL_UNCAL` | soil_a/b | info의 `soil_cal = 0` | — | info | 토양 보정 마법사로 |
| `SOIL_AB_DIFF` | soil_b | \|A − B\| > 0.25 | 10분 | warn | 꽂은 깊이, 흙 다짐, 물 떨어지는 위치 |
| `SOIL_NO_RISE` | soil_a/b | 급수 후 15분 안에 무게는 늘었는데(+예상량 50% 이상) 수분은 0.02 이하로 오름 | — | warn | 센서 깊이·흙 접촉, 물이 한쪽으로만 흐름 |
| `SOIL_STUCK` | soil_a/b | 6시간 동안 변화 10mV 이하 | 6시간 | info | 너무 마르거나 젖음, 센서 확인 |
| `LC_NO_RESP` | scale | `hx_ok = 0` | 15초 | fault | HX711 배선(DT/SCK), 3.3V 전원 |
| `LC_UNCAL` | scale | `lc_cal = 0` 또는 weight_g null이고 hx_ok=1 | — | info | 로드셀 보정 마법사로 |
| `LC_NOISY` | scale | `weight_sd` > 5g | 2분 | warn | 케이블이 판을 당김, 판이 닿음, 바람·진동 |
| `LC_NEGATIVE` | scale | weight_g < −50 | 1분 | warn | 화분 올린 채 영점 잡음, 판 닿음 |
| `LC_OVERLOAD` | scale | weight_g > 7000 | 즉시 | fault | 정격 초과 (10kg 센서, 7kg 이하 운용) |
| `LC_DRIFT_UP` | scale | 급수·메모 없이 1시간에 +20g 이상 | 1시간 | warn | 무언가 판에 기댐, 온도 드리프트 |
| `WATER_NOT_ARRIVED` | pump | `pump_off(done)` 후 2분 안에 무게 증가 < 예상 mL의 50% | — | fault | 튜브 막힘·꺾임, 펌프 헤드, 출수구가 화분 밖 |
| `WATER_OVER` | pump | 무게 증가 > 예상 mL의 150% | — | warn | 유량 보정 다시, 사이펀 |
| `PUMP_REFUSED` | pump | `refused` 사건 | 표시 2분 | warn | reason별 안내 |
| `FLOW_UNCAL` | pump | `pump_mlps = 0` | — | info | 유량 보정 마법사로 |
| `V12_MISSING` | power | v12 < 9.0 | 3초 | warn | 비상정지 눌림, 분기 퓨즈, 어댑터 |
| `LEAK` | power | leak = 1 | 즉시 | fault | 받침 위 물기 제거, 튜브 연결부 |

`WATER_*` 판정은 무게 흔들림(`weight_sd`)이 3g 이하로 안정된 값끼리 비교한다. 물 1mL = 1g으로 본다.
